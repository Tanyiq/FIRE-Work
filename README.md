# 退休计划（FIRE Work）

> 当前版本：`1.0.0-beta.1`

一款使用微信原生小程序与 TypeScript 开发的个人财富成长档案。它帮助用户记录资产、理解自由进度、复盘投资决策，并收藏财富真正创造的人生经历。

产品不提供股票行情、收益预测、买卖建议或市场判断。

## 当前功能

- 自由档案：首页展示距离梦想生活、连续自由等级、积累阶段、当前资产、近一年变化和人生收藏数量。
- 首次使用引导：依次完成梦想生活、当前资产、生活成本和第一段人生收藏。
- 财富管家：维护现金、定存、基金、红利、股票、黄金和其他资产，并生成每日财富快照。
- 财富健康与建议：根据生活成本、资产结构、快照趋势和投资复盘生成可解释的状态提示。
- 生活成本：维护基础与舒适生活成本，并展示 2%、3%、4% 三套 FIRE 参考方案。
- 投资复盘馆：记录投资理由与复盘，不修改资产总额，不预测未来结果。
- 人生博物馆：记录实物、经历、人生事件和收益事件，计算陪伴天数与每日成本。
- 财富报告：比较相邻财富快照，记录变化来源并生成本地总结。
- 年度财富回顾：汇总年度资产变化、自由等级、记录习惯、人生消费和投资教训。
- 年度分享图：在本地 Canvas 生成年度摘要图片，并通过微信图片分享面板分享；不包含资产明细和投资明细。
- 个人财富档案：导出、校验并恢复版本化 JSON 备份。
- beta 体验：统一 Design Token、首页成长动效、年度切换动效、档案建立完成态和历史数据保护说明。

## 技术方案

- 微信原生小程序
- TypeScript
- WXML + WXSS
- 微信本地 Storage
- 微信原生 Canvas
- 无后端、无云数据库、无第三方图表依赖

页面只负责交互和展示，计算、校验与持久化集中在 `services`，数据契约集中在 `models`，格式化和绘图放在 `utils`。

视觉规范见 [docs/DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md)，历史数据规则见 [docs/DATA_INTEGRITY.md](docs/DATA_INTEGRITY.md)。

## 核心数据约定

- 金额统一以“元”存储，页面按需要显示为元或万元。
- 自由正式目标仍为 Lv1 60 万、Lv2 120 万、Lv3 200 万、Lv4 500 万。
- 首页连续自由等级仅用于展示阶段内进度，不修改正式目标。
- 同一天内多次修改资产会合并到当天快照，不产生重复趋势节点。
- 年度回顾和分享图由已有数据即时生成，不新增 Storage 数据。
- FIRE 方案根据基础生活成本实时计算，不覆盖用户选择的生活等级目标。

## 启动方式

1. 安装并打开微信开发者工具。
2. 选择“导入项目”，目录选择本仓库根目录。
3. 确认 `project.config.json` 中 `miniprogramRoot` 为 `miniprogram/`。
4. 点击“编译”。

项目使用微信开发者工具内置的 TypeScript 编译能力，不需要单独启动服务器。

## Milestone 11 测试建议

1. 在开发者工具中清除本地 Storage，重新编译。
2. 确认自由页显示“创建你的财富档案”和四步引导。
3. 选择 Lv1-Lv4 任一目标，确认进入“我的自由档案”，并显示剩余进度、连续等级与积累阶段。
4. 按引导依次添加资产、填写生活成本、添加人生收藏，确认完成数从 1/4 更新到 4/4，完成后引导卡自动隐藏。
5. 修改资产，确认当前资产与距离目标同步更新；存在跨年快照时，确认“过去一年”变化正确。
6. 分别清空资产、人生收藏和投资记录，确认空状态包含用途解释及可点击的下一步按钮。
7. 进入“报告 → 我的财富年度回顾”，选择有数据的年份，点击“生成年度分享图”。
8. 确认图片分享面板正常打开，海报包含年度、资产变化、自由成长和记录次数，但不包含资产或投资明细。
9. 返回各页面再次编译，确认已有本地数据未被清除。

## Milestone 12 测试建议

1. 打开自由档案，确认资产数字、剩余比例和进度条在约 420ms 内平滑抵达真实值。
2. 完成四步引导，确认出现“你的财富档案已建立”和四项完成标记。
3. 在年度回顾切换年份，确认内容使用短距离淡入，不影响年份数据准确性。
4. 在财富页创建资产，跨日形成快照后删除该资产，确认旧日期快照仍存在，今天的快照反映删除后的总额。
5. 对人生收藏修改开始日期，确认 `createdAt` 不变，陪伴天数和每日成本重新计算。
6. 打开“我的 → 数据管理”，确认历史数据保护卡展示快照数、报告数和三条保护规则。
7. 生成新报告，确认系统使用今天的快照，不覆盖此前日期报告。
8. 导出并恢复 JSON 备份，确认完整档案仍可校验和恢复。
